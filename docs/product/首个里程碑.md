# M0：微信驱动的自进化 Wiki 闭环

> 日期：2026-08-06
> 状态：ready for issue breakdown

## 目标

用户在微信中提交两篇观点相关或冲突的公众号文章，FlyWiki 保存可复核快照，允许用户编辑派生 Markdown，使用 OpenKB 更新 Wiki，展示 Knowledge Delta 和一跳证据图，并在微信中返回带原文引用的回答。

## 演示路径

1. Owner 用二维码绑定微信，Channel Binding 指向默认 Knowledge Base。
2. Owner 发送第一篇公众号或公开网页链接；系统数秒内返回接收确认。
3. Capture Pipeline 异步保存原始 HTML、清洗 Markdown、元数据、附件与 locator，并创建 Editable Note。
4. 用户在 Web 中预览、编辑并保存 Markdown；Source Version 保持不变。
5. OpenKB Worker 编译 Wiki；受限 DeepAgents Run 分析 Claim、Evidence Span 和 Evidence Relation，并向确定性 Module 提交 Knowledge Change Set 提案。
6. Owner 再发送一篇观点相关或冲突的文章；系统识别新增、强化或需要认知更新。
7. Knowledge Inbox 展示变化、原文上下文和一跳局部图；冲突项允许接受新观点、保留双方、维持原观点或稍后处理。
8. Owner 在微信提问；系统只依据默认 Knowledge Base 回答，并同时引用两篇原文。证据不足时明确回答不知道。

## 验收标准

- 单命令 Docker Compose 可启动 Web、API、Worker、PostgreSQL、Redis、对象存储、固定版本 OpenKB Worker 与固定版本 Langfuse。
- 未绑定身份不能调用模型或读取 Workspace 数据；首版 allowlist 只有 Owner。
- 相同微信消息或 URL 重放不会创建重复 Source Version 或重复编译任务。
- 链接提交采用即时确认、可查询进度、完成/失败通知；失败可重试。
- 原始网页快照不可变；Editable Note 的每次保存可追踪版本。
- 每个事实 Claim 至少关联一个可打开原文上下文的 Evidence Span。
- 第二篇文章能产生至少一条可解释 Knowledge Delta，并展示分类理由与适用边界。
- 自动应用的知识变化可回滚；冲突、替代和删除未经审阅不得生效。
- 微信回答中的事实 Claim 通过引用审计；无证据时不使用模型常识补答。
- OpenKB 数据删除后可以从 FlyWiki 规范数据重建 Wiki 与一跳 Graph Projection。
- 关键链路在 Langfuse 中形成稳定 Trace/Observation，且能关联成本、延迟、工具调用、引用审计与任务结果。
- M0 评测 Dataset 能运行 DeepAgents 配置实验，并用引用覆盖、locator、groundedness 和工具拒绝 Scores 阻断回归。
- Langfuse 不可用时核心任务继续运行，并明确报告观测降级。

## 明确不包含

- RSS/YouTube 自动订阅与 X Adapter；
- 浏览器扩展；
- Obsidian 双向同步；
- 全库图谱无限画布、聚类与手工布局；
- 多用户、角色、分享、计费、企业后台；
- 本地模型质量承诺；
- 飞书、Telegram 或其他消息 Channel；
- OpenClaw 运行依赖，以及 DeepAgents 的任意 Shell、文件系统或直接数据库写权限。

## 后续顺序
