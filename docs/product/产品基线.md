# FlyWiki 产品基线

> 版本：v2.0
> 日期：2026-08-06
> 状态：当前权威基线
> 决策者：项目发起人

相关文档：[领域词汇表](../../CONTEXT.md) · [ADR](../adr/) · [首个里程碑](首个里程碑.md)

## 1. 产品承诺

FlyWiki 是单用户自托管的 LLM Wiki。它把用户主动保存和持续订阅的内容编译为可追溯、可演化的 Wiki，维护 Claim、Evidence Span、冲突和 Graph Projection，并通过 Web 与消息 Channel 提供 grounded chat。

项目已经决定交付产品。用户验证、质量评测和 dogfood 仍然决定优先级、交互和质量门槛，但不再作为是否开发产品的 Go/Hold/Stop Gate。触发质量红线时停止发布并修复或收缩，不终止产品方向。

## 2. 首发边界

- 单用户、自托管、Docker Compose 交付；所有领域数据仍包含 `workspace_id`。
- Workspace Owner 是根身份；首发不做注册平台、计费、多角色、企业管理后台或多人协作。
- OpenKB 是隔离、固定版本、可替换的知识编译器，不是领域真相源。
- OpenClaw 不是运行依赖；FlyWiki 自己定义 Channel 端口。
- 首个 Channel 是 `WeixinChannel`，通过腾讯 iLink Bot 协议二维码授权，只允许 Owner 私聊。
- 数据与服务在自托管实例；推理默认使用用户自己的云模型 API Key。LiteLLM 保持供应商可替换，本地模型仅尽力兼容。
- 个人核心以 Apache-2.0 开源；未来商业化放在托管服务、模型额度、团队治理和企业连接器。

## 3. 知识与内容模型

### 3.1 不可变证据与可编辑内容

- Source 表示外部资料的逻辑身份。
- Source Version 是不可变快照。网页默认保存原始 HTML、清洗 Markdown、元数据、下载附件和 locator 映射；整页截图可选。
- Editable Note 是用户可编辑、可版本化的 Markdown。富文本只是编辑视图，不能覆盖 Source Version。
- Editable Note 可以参与编译，但生成的 Claim 必须区分原始来源与用户改写。

### 3.2 自动演化边界

- Compiled Knowledge 可以自动更新，每次更新必须形成可审计、可回滚的 Knowledge Change Set。
- 新增与强化可以按治理规则自动应用。
- 冲突、替代和删除只能形成 Change Proposal，必须由用户审阅。
- Belief 只能由用户明确改变；模型只能提出理由与候选动作。
- 冲突审阅支持：接受新观点、保留双方并补充适用边界、维持原观点、稍后处理。

### 3.3 真相源与图谱

PostgreSQL 中的 Source Version、Evidence Span、Claim、Evidence Relation 与 Knowledge Change Set 是规范数据。OpenKB Wiki、搜索索引和 Graph Projection 都可以从规范数据重建。首个里程碑只提供一跳局部图，用于从 Claim 导航到证据与相邻关系；全库无限画布、聚类和布局编辑后置。

## 4. Knowledge Delta 与可信问答

领域层保留七类 Knowledge Delta：新增、强化、限制、冲突、替代、重复和低价值。产品界面收敛为四类：新增、强化、需要认知更新、忽略。判断必须记录适用时间、对象、条件、置信度和证据，避免把范围差异误报为直接矛盾。

聊天默认只使用当前 Knowledge Base 的可引用证据。证据不足时明确回答不知道并展示知识缺口。联网研究必须由用户显式开启；发现的资料先创建 Source Version，再参与回答。

每个 Channel Binding 绑定一个默认 Knowledge Base。普通消息和链接都进入默认库；用户可以显式切换或在消息中指定目标库，模型不得猜测写入目标。

## 5. 采集、编辑与订阅

- Web 输入框与 WeixinChannel 先共用 Capture Pipeline。
- 链接提交在数秒内返回接收确认；抓取、快照、编译、变化分析在后台执行，完成或失败后主动通知。
- 消息、Source、Source Version 和编译任务都有幂等键；重复投递不得产生重复知识。
- 编辑内容以 Markdown 为规范格式，界面提供所见即所得编辑、模板字段、标签、批注与附件管理。
- 自动订阅首批支持 RSS/Atom、普通博客页面和 YouTube 频道/字幕；用户始终可以手动提交公开链接。
- X 只提供 BYOK 可选 Adapter，不作为核心可用性的依赖。
- 浏览器扩展在首个闭环稳定后交付，复用 Capture Pipeline 和编辑组件。
- Obsidian 首版提供单向兼容导出，不做双向同步。

## 6. 体验与信息架构

Knowledge Inbox 是默认首页，优先呈现新内容处理状态、Knowledge Delta、Change Proposal 和失败任务。Wiki Browser、Sources、Graph Projection 和 Chat 是二级工作区。

视觉与交互参考 Cubox 的阅读密度、WeKnora 的知识库导航和关系面板，以及 Obsidian Web Clipper 的模板化采集与 Markdown 编辑行为；只参考产品行为和视觉原则，不复制受保护实现或品牌元素。

## 7. 发布纪律

- 首个可演示闭环以[首个里程碑](首个里程碑.md)为准。
- locator、引用完整性、多轮编译保真、权限、幂等和回滚仍是发布门禁。
- 评测失败时不得降低证据与安全门槛；可以缩小来源、模型或功能范围后重测。
- 旧 PRD、可行性分析和 R0 计划保留为研究与决策演进记录，不再定义当前范围。
