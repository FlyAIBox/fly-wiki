# 互联网采集能力

本文描述 FlyWiki **当前代码和标准 Docker Compose 实际提供**的互联网采集能力。Agent Reach skill 自身支持的平台更多，但只有经过 FlyWiki Capability Gateway 和 Acquisition Adapter 接入的能力，才算 FlyWiki 已支持。

## 状态定义

| 状态 | 含义 |
|---|---|
| 开箱可用 | 标准 Compose 不需要额外 CLI 或登录态即可运行 |
| 条件可用 | FlyWiki 已有专用 Adapter，但运行环境还需安装 CLI、配置登录态或凭证 |
| 通用回退 | 没有可用的专用 Adapter 时，只尝试 Jina Reader 或安全 HTML 抓取，不能保证获得平台完整正文、评论或互动数据 |
| 尚未接入 | Agent Reach skill 有对应能力，但 FlyWiki 尚未把它暴露为受控 Capability |

## 采集路由

FlyWiki 对每个 URL 按以下顺序采集：

1. `AgentReachSocialFetcher` 尝试社交平台专用只读路由；
2. `WeChatPublicAccountFetcher` 使用内置 `web-content-fetcher` skill 采集微信公众号文章，优先直取并在内容不足时自动使用 stealth 浏览器；
3. `AgentReachWebFetcher` 使用 Jina Reader 把其他公开网页标准化为 Markdown；
4. `SafeWebFetcher` 直接读取公开 HTML，并执行 SSRF、DNS、重定向、Content-Type 和大小限制；
5. 成功结果先写入不可变 Source Version，再生成 Editable Note；DeepAgents 只能在证据落库后看到正文。

采集使用哪个后端会写入 `metadata.json` 的 `capture_backend`，例如 `agent-reach:v2ex`、`web-content-fetcher:wechat`、`agent-reach` 或 `safe-web`。

微信公众号专用路径的 skill 用法、Adapter 协议、部署依赖和排障方法见[《微信公众号采集与 `web-content-fetcher` skill》](../runbooks/微信公众号采集与-web-content-fetcher.md)。

## 社交平台与社区

| 平台 | 当前专用 URL 能力 | 专用后端 | 标准 Compose 状态 | 限制与回退 |
|---|---|---|---|---|
| V2EX | 读取 `/t/{topic_id}` 主题正文和第一页回复 | V2EX 公开 API | 开箱可用 | 热门、节点列表、用户信息尚未接入；其他 URL 走通用回退 |
| X / Twitter | 读取单条状态 URL | `twitter tweet URL` | 条件可用 | 需安装 `twitter-cli`，并显式配置 `TWITTER_AUTH_TOKEN`、`TWITTER_CT0`；搜索、Feed、用户时间线、Article 专用路由尚未接入 |
| 小红书 | 读取包含 `xsec_token` 的 `/explore/` 笔记 URL | OpenCLI；备用 `xhs read` | 条件可用 | 需已有登录态或手工导入 Cookie；不能只传裸 note id；搜索、Feed、评论、用户页尚未接入 |
| Bilibili | 读取 `/video/BV...` 视频详情 | `bili video`；备用 OpenCLI | 条件可用 | `bili-cli` 的视频详情通常无需登录；搜索、热门、字幕、音频转写尚未接入 |
| Reddit | 读取 `/comments/{post_id}` 帖子及后端返回的评论 | OpenCLI；备用 `rdt read` | 条件可用 | 必须有登录态；搜索、Subreddit、热门列表尚未接入 |
| Facebook | 读取形如 `facebook.com/{username}` 的用户或主页信息 | OpenCLI | 条件可用 | 必须复用用户已有 Chrome 登录态；帖子详情、Feed、Groups 尚未接入 |
| Instagram | 读取形如 `instagram.com/{username}` 的用户最近帖子 | OpenCLI | 条件可用 | 必须复用用户已有 Chrome 登录态；`/p/`、Reels、Explore、Saved 和关键词搜索尚未接入 |

标准 API/Worker 镜像目前不内置上述社交 CLI，也不持有浏览器登录态。因此除 V2EX 外，当前 Compose 中的社交 URL 实际会继续尝试通用网页回退。回退成功只代表获取到了公开网页内容，不等于专用能力可用，也不保证包含评论、互动数据或登录后内容。

Reddit 没有匿名零配置路径。Jina Reader 返回的 `Target URL returned error 403`、`You've been blocked by network security` 等内容属于拦截页，不是帖子正文；FlyWiki 会把带有上游 4xx/5xx 标记的 Reader 响应判为失败，不创建伪证据。要稳定采集 Reddit，必须在受控运行环境中配置已有登录态的 OpenCLI，或安装并登录 `rdt-cli`。

所有社交能力均为只读。FlyWiki 不执行发帖、评论、点赞、关注、私信或自动登录。

## 通用网页与下载

| 能力 | 状态 | 行为与限制 |
|---|---|---|
| 公开网页 URL | 开箱可用 | 优先走 Jina Reader，失败后直接读取公开 HTML/XHTML |
| 微信公众号文章 | 开箱可用 | 专用 Adapter 只接受 `mp.weixin.qq.com/s/...`，提取正文、标题、作者和发布时间；直取内容不足时自动使用 stealth 浏览器，失败后才走通用回退 |
| HTML 转 Markdown | 开箱可用 | 去除脚本、样式、模板等内容，提取标题、作者、发布时间和正文 |
| Locator Map | 开箱可用 | 为标题、段落、列表项记录顺序和文本哈希，供后续证据定位 |
| 页面图片 | 部分支持 | 原生 HTML 提取路径会发现最多 20 个 `<img src>` 并安全下载；Jina Reader 返回 Markdown 时目前不会继续发现图片附件 |
| PDF 附件下载 | 部分支持 | 附件下载器接受 `application/pdf`，但当前页面提取器不会自动发现普通 PDF 链接 |
| 直接 PDF URL | 尚未接入 | 当前页面抓取只接受 HTML/XHTML；需增加 PDF Extractor |
| RSS/Atom | 尚未接入 | Agent Reach skill 有 feedparser 路由，但 FlyWiki 尚无 RSS Capability Adapter |
| 需要 JavaScript 渲染的网页 | 通用回退 | Jina Reader 可能成功；FlyWiki 原生抓取器不运行浏览器 JavaScript |
| 登录墙、验证码、反爬页面 | 不保证 | 不绕过平台限制；需要平台允许的登录态专用 Adapter |

每次成功采集会保存：

- 原始响应 `raw_html`（名称沿用证据 Artifact 角色，内容也可能是 Agent Reach 返回的 Markdown）；
- 标准化正文 `content.md`；
- 元数据 `metadata.json`；
- 定位信息 `locators.json`；
- 成功下载的图片或其他附件；
- 对应的 Editable Note 初始版本。

## DeepAgents 当前可用范围

DeepAgents 已加载 `skills/agent-reach/`，但没有通用 Shell、浏览器、任意网络或数据库权限。当前只开放一个 Workspace 范围的工具：

```text
acquire_source(url)
```

因此 Agent Run 目前适合“读取给定 URL 并总结、比较或提取证据”。它不能仅凭关键词调用 Exa 搜索，也不能直接执行 Agent Reach 文档里的 CLI 命令。每个 URL 的结果必须先由 Capability Gateway 创建 Source Version，之后才能返回给模型。

## Agent Reach 中存在但 FlyWiki 尚未开放的能力

以下能力在 Agent Reach skill 中有路由说明，但当前 FlyWiki 没有对应的受控 Tool/Adapter，不能算已经支持：

- Exa 网页搜索和中文搜索；
- GitHub 仓库、Issue、PR 和代码搜索；
- LinkedIn、招聘和职位搜索；
- YouTube 字幕、B站字幕、播客和小宇宙转写；
- RSS/Atom 订阅发现与轮询；
- 雪球、股票行情和金融内容；
- 各社交平台的关键词搜索、Feed、热门、用户列表、评论深翻等非 URL Capture 操作。

后续接入这些能力时，应增加新的 Capability Interface 和 Adapter，而不是把 Shell 直接交给 DeepAgents。这样可以继续保留 Workspace 授权、幂等、配额、审计和不可变证据边界。

## 安全边界

- 只允许 `http` 和 `https` URL，不允许 URL userinfo；
- 每次请求和重定向都重新检查 DNS，拒绝本机、内网和非公网 IP；
- 页面、附件、重定向次数和超时都有配置上限；
- Cookie、Token 和浏览器登录态不写入 Source、普通日志或 Agent 上下文；
- 平台专用能力失败时可以降级，但不能绕过 Workspace 和 SSRF 检查；
- HTTP 200 不代表正文有效；Jina Warning、登录墙、CAPTCHA 和“环境异常/完成验证”等挑战页会以 `blocked_content` 拒绝；
- DeepAgents 不直接写知识库；采集和 Source Version 写入由确定性 Module 完成。
