## 0. 本文定位

[可行性分析](可行性分析.md)第 8-9 节已经约定了 R0 的实验清单、成功门槛与 Go/Hold/Stop 判据。本文不重新论证，只把它落成**可执行**的东西：每个实验拆成步骤、交付物、度量方式与时间盒，并明确“为跑通实验最少要搭什么”。

**当前红线**：触发原 Stop 判据时停止发布、复盘并修复或收缩范围，不停止产品方向。

## 1. R0 五个实验与依赖关系

可行性分析定义了五个实验，它们对“最小基建”的依赖不同。按“能否独立开跑”排序，得到三条并行轨：

| 轨 | 实验 | 依赖基建 | 能否立即开跑 |
| --- | --- | --- | --- |
| A（人工/离线） | 四分类标注集、Locator 基准 | 仅需语料 + 标注表格 + 少量脚本 | ✅ 立即，可先于任何服务 |
| B（技术 PoC） | OpenKB 十轮回放 | 固定版本 OpenKB Worker + Adapter + 语料 | ⚠️ 需先搭 OpenKB 隔离壳 |
| C（用户行为） | 自我 dogfood 两周、外部数据与主题承诺 | 需要 A+B 产出的最小可用管道 | ⛔ 最后开跑，依赖前两轨 |

**关键排序逻辑**：C 轨（价值验证）是项目命门，但它依赖一条“导入→编译→Delta→Digest”的最小管道，而这条管道的可信度又取决于 A、B 两轨先证明证据内核和编译不退化。因此执行顺序是 **A ∥ B 先行 → 打通最小管道 → C 压轴**。

## 2. 时间盒总览

单人 + AI 辅助，不给精确人月承诺，改用**时间盒 + 早停信号**。每个盒子超期即触发 Hold 复盘（收缩范围），而不是默认延长。

| 阶段 | 时间盒 | 主要产出 | 早停信号 |
| --- | --- | --- | --- |
| P0 语料与标注基建 | 1 周 | 冻结语料集、标注规范、评分脚本 | 凑不齐 1000 份真实混合语料 |
| P1 A 轨：标注集 + Locator 基准 | 1-2 周 | 50 组标注、locator 基准集、两份评分报告 | locator 明显 <98% 且错误不可解释 |
| P2 B 轨：OpenKB 十轮回放 | 1-2 周 | OpenKB Worker 壳、Adapter、十轮回放报告 | 关键 Claim 丢失或无法回退 |
| P3 最小价值管道 | 2-3 周 | 导入→编译→Delta→Digest 的最小闭环 | 管道无法端到端产出可读 Digest |
| P4 C 轨：dogfood 两周 | 2 周（连续） | 每日使用记录、漏检变化清单 | 开发者本人第二周弃用 |
| P5 C 轨：外部承诺 | 与 P4 部分重叠，2-3 周 | 3-5 名外部用户导入 + 反馈 | 招不到人 / 无人愿交真实资料 |
| Gate | 1-2 天 | Go/Hold/Stop 评审纪要 | — |

P1、P2 并行；P4、P5 部分重叠。乐观路径约 8-10 周，但**时间不是验收标准，门槛才是**。

## 3. 实验详拆

### 3.1 实验 A1：四分类标注集

**验证假设**（可行性 #3）：Claim—Evidence 关系与 Knowledge Delta 四分类能否达到推送门槛。

**成功门槛**（沿用可行性分析，不下调）：
- ≥50 组人工标注的 Claim—Evidence 与 Knowledge Delta 关系，覆盖四分类边界样本；
- 四分类（世界新知识 / 可能需要认知更新 / 强化 / 值得阅读·忽略）Precision ≥80%；
- 易混对（强化 vs 忽略、冲突内部子标签）单独报告。

**步骤**：
1. 从冻结语料里选 15-25 个主题簇，每簇准备“已有知识 + 一条新证据”样本对；
2. 人工先给金标签（四分类 + 冲突子标签：限制/替代）；标注规范与边界判例写入 `evals/labeling-guide.md`；
3. 用当前候选 Prompt/模型跑一遍分类，输出机器标签；
4. 脚本比对，产出混淆矩阵、逐类 Precision/Recall、易混对清单。

**交付物**：`evals/delta-annotations.jsonl`（金标签）、`evals/labeling-guide.md`、`evals/report-delta.md`（评分报告）。

**度量工具**：一个 Python 评分脚本（读 jsonl，出混淆矩阵与逐类指标），不依赖任何服务。

---

### 3.2 实验 A2：Locator 基准

**验证假设**（可行性 #3）：引用能否被精确复核。

**成功门槛**：PDF 页码、网页段落、图片区域、音视频时间码的 **locator 有效率 ≥98%**（硬指标，不因单人规模下调），错误可解释。

**步骤**：
1. 从冻结语料抽覆盖四种介质的定位点，人工记录“正确 locator”作为金标准；
2. 跑当前抽取管道产出 locator；
3. 脚本判定每个 locator 能否被程序重新解析回原文片段（可自动化，不靠人力堆）；
4. 失效项归因分类（解析库缺陷 / 介质特例 / 编码问题）。

**交付物**：`evals/locator-benchmark.jsonl`、`evals/report-locator.md`（含失效归因）。

**度量工具**：locator 回解脚本——给定 (source_version, locator) 能否稳定取回预期片段。

> A2 是四个技术门槛里唯一**纯自动化、无主观**的一项，应最先做完，它能最快给出“证据内核是否可信”的硬信号。

---

### 3.3 实验 B1：OpenKB 十轮回放

**验证假设**（可行性 #4，ADR-0001）：OpenKB 可隔离升级且多轮编译不退化。

**成功门槛**：
- 1000 份混合 Source 完成初次编译、增量添加、删除预演、失败恢复、重建；
- 连续 10 轮增量摄取后关键 Claim 不丢失、旧 Evidence Span 仍可定位；
- 固定版本重建结果可比较，升级失败能在不污染领域数据的前提下回退；
- 业务代码除 Adapter/扩展外不 import OpenKB 或 OpenAI Agents SDK。

**步骤**：
1. 搭 OpenKB 独立 Worker（固定版本 + digest），只经 `OpenKBAdapter` 调用；写一个测试用 Fake Adapter 供离线测；
2. 同一语料按时间分 10 批增量摄取，每轮快照关键 Claim 集合与 locator；
3. 人工黄金版本对照，逐轮 diff 关键 Claim 存活率与 locator 有效率；
4. 演练：删除、失败恢复、固定版重建、升级到新版后回退。

**交付物**：OpenKB Worker 壳 + `OpenKBAdapter` + Fake Adapter、`evals/openkb-replay.md`（十轮 diff 报告 + 回退演练记录）。

**依赖检查**：跑 `import` 静态扫描，确认业务 Module 不直接依赖 OpenKB/OpenAI Agents SDK（对应 ADR-0001 隔离要求）。

---

### 3.4 实验 C1：自我 dogfood 两周

**验证假设**（可行性 #1、#2、#5，北极星行为）：认知推送是否创造持续价值。这是**最低成本证伪**——开发者本人既是执行者又是目标用户。

**前置**：P3 最小价值管道可用（见 §4）。

**成功门槛**：
- 开发者本人用真实资料 + ≥1 个真实追踪主题，连续两周审阅 Digest；
- 两周后仍主动使用；
- 能指出至少一条“靠原有流程会漏掉”的重要变化。

**步骤**：
1. 导入本人真实积压资料（目标 ≥100 条），配置 1 个 Watch Rule；
2. 每天/每次推送后填一行使用日志：是否打开、是否有价值、是否发现漏检变化；
3. 用“接受”确认少量 Belief，观察是否构成整理负担（验证 #5）；
4. 两周末做自评：是否愿意继续用。

**交付物**：`evals/dogfood-log.md`（逐日记录）、漏检变化清单、Belief 确认负担自评。

**Stop 信号**：开发者本人第二周不再主动使用 → 直接 Stop（自己都不用，别人更不会）。

---

### 3.5 实验 C2：外部数据与主题承诺

**验证假设**（可行性 #1）：外部用户是否愿意交真实数据并持续追踪。

**成功门槛**：
- 从熟人/社群招募，3-5 人完成导入（各备 ≥100 条资料 + 1 个追踪主题）；
- 至少 2 人连续两周主动打开 Digest 并给反馈；
- 每位持续使用者能指出至少一条原本会漏掉的重要变化。

**步骤**：
1. 招募：定向找“每周持续接收新资料且经常积压”的知识工作者；
2. 引导导入 + 配置 Watch Rule（可陪同/半人工）；
3. 观测两周真实打开与反馈行为，不用“觉得有用/愿意以后用”的口头承诺替代；
4. 收集漏检变化实例。

**交付物**：`evals/external-users.md`（招募、导入完成度、两周行为、漏检实例）。

## 4. 为跑 C 轨最少要搭什么（P3 最小价值管道）

C 轨不能在空气里跑，但也**绝不等于开发一期**。P3 只搭“导入→编译→Delta→Digest”够 dogfood 用的最薄切片：

**必须有**：
- Workspace + 单 Knowledge Base（应用层 `workspace_id` 过滤，够单人用即可）；
- Source Registry：文件/网页上传 → 不可变 Source Version；
- OpenKB 编译（复用 B1 的 Worker + Adapter）；
- Evidence Graph 最小形态：Claim + Evidence Span + locator（复用 A 轨内核）；
- Watch Rule + 抓取 + 四分类 Delta（复用 A1 分类器）；
- Knowledge Digest：能按四分类产出一份可读推送（Web 或直接飞书/邮件均可）；
- 一条能看 Digest 的入口（简陋 Web 或飞书私聊皆可）。

**明确不做（留到 R1）**：
- 图谱可视化、Knowledge Inbox 完整视图、健康中心、MCP、插件、多入口、导出/备份、部署预检、权限体系。

**判据**：P3 的唯一验收是“能端到端产出一份基于真实资料、四分类正确的 Digest”，不追求界面完整度。

## 5. R0 目录与交付物约定

R0 产出集中在两处，避免污染一期代码：

```
evals/                          ← 所有基准集、标注、评分报告
├── labeling-guide.md
├── delta-annotations.jsonl
├── locator-benchmark.jsonl
├── report-delta.md
├── report-locator.md
├── openkb-replay.md
├── dogfood-log.md
└── external-users.md
src/ (或 poc/)                  ← 最小管道 + OpenKB 壳 + 评分脚本
```

> 语料本身可能含敏感/版权资料，冻结语料清单入库、原文不入库（用哈希/路径引用），与技术方案 §15 内容权利一致。

## 6. Gate 决策清单

R0 结束时对照可行性分析第 9 节，逐条打勾：

**Go（进入 R1-R2）——全部满足**：
- [ ] 开发者本人连续两周真实使用且愿意继续；
- [ ] ≥2 名外部用户连续两周主动打开并反馈；
- [ ] 每位持续使用者指出 ≥1 条原本会漏掉的重要变化；
- [ ] 四分类 Precision ≥80%；
- [ ] locator ≥98%；
- [ ] OpenKB 十轮编译 + 回退 + Workspace 隔离基准通过；
- [ ] 飞书 Spike 可用。

**Hold（调整后复测）——命中任一**：
- [ ] 价值成立但 Belief 确认/图谱/推送造成认知负担；
- [ ] 技术基准过，但用户只审第一周、第二周弃用；
- [ ] 某个时间盒超期，需收缩范围后复测节奏。

**Stop / Pivot——命中任一**：
- [ ] 开发者本人两周后不再主动使用；
- [ ] 外部用户不愿交真实资料 / 设主题 / 连续审阅；
- [ ] Digest 不优于人工阅读或通用摘要；
- [ ] locator 或多轮编译保真达不到门槛且无可接受人工复核成本；
- [ ] 单次任务成本超个人试验预算且无法通过路由/缓存/配额控制。

## 7. 立即可开始的三步

不必等基建齐全，以下三件事今天就能推进，且互不阻塞：

1. **冻结语料集（P0）**——把本人真实积压资料整理成 ≥1000 份混合集，出一份 `evals/corpus-manifest`（哈希 + 介质 + 主题标签）。这是 A、B、C 三轨共同的输入。
2. **写标注规范 + 评分脚本（A 轨）**——四分类边界判例 + locator 回解判定，纯离线，最先能给硬信号。
3. **搭 OpenKB 隔离壳（B 轨）**——固定版本 Worker + `OpenKBAdapter` + Fake Adapter，为十轮回放和 P3 管道打底。
