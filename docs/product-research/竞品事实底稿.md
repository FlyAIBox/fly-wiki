# FlyWiki 一期竞品事实底稿

> 调研日期：2026-08-01
>
> 调研范围：以 OpenKB 为可升级知识编译器、具备知识图谱、持续追踪与推送、可信写作、微信/飞书入口、浏览器剪藏、知识库分享与访客投稿的 FlyWiki 一期。
>
> 证据规则：只采用厂商官方文档、官方产品/价格页、官方 GitHub 仓库、源码、Release 与提交记录。本文不推断市场份额，也不把 README 宣传语自动等同于完整实现。

## 1. 结论摘要

本轮选择五个直接或最接近的产品作为主比较对象：**Tencent WeKnora、RAGFlow、Onyx、Khoj、AnythingLLM**。OpenKB 是 FlyWiki 已确定采用的底座，不适合与上面五项等同看待，因此单列为能力基线；Obsidian + Web Clipper、NotebookLM 分别代表“本地文件与剪藏”和“可信问答与公开分享”两条邻接路线。

### 1.1 已证实的市场事实

1. **WeKnora 是当前功能面最接近 FlyWiki 的单一开源产品。**它同时公开了 Auto-Wiki/交互图谱、增量数据源、微信与飞书等 IM、Chrome 剪藏、网站 Embed、跨组织知识库分享和多 Workspace RBAC。[官方定位与能力总览](https://github.com/Tencent/WeKnora/blob/5780affdfc76342ddd0f5cf95b548a1a4d0b2a5a/README.md#L47-L55) · [集成与权限矩阵](https://github.com/Tencent/WeKnora/blob/5780affdfc76342ddd0f5cf95b548a1a4d0b2a5a/README.md#L133-L156)
2. **RAGFlow 已不只是传统 RAG。**公开文档已有数据集级知识图谱、引用、团队权限、MCP 和飞书等聊天通道；截至本次快照，主分支还出现了可分派 `structure/wiki/tree/mindmap/datasetnav` 的 `KnowledgeCompiler` 组件与内置摄取模板，但 README/发布说明尚未把它作为稳定产品能力介绍。[知识图谱文档](https://github.com/infiniflow/ragflow/blob/776b9371f7f8a7ef44161d5ed01805ceaa0e244d/docs/guides/dataset/advanced/construct_knowledge_graph.md#L10-L30) · [KnowledgeCompiler 源码](https://github.com/infiniflow/ragflow/blob/776b9371f7f8a7ef44161d5ed01805ceaa0e244d/internal/ingestion/component/knowledge_compiler/component.go#L1-L82) · [内置模板](https://github.com/infiniflow/ragflow/blob/776b9371f7f8a7ef44161d5ed01805ceaa0e244d/internal/ingestion/pipeline/template/ingestion_pipeline_knowledge_compiler.json#L1-L13)
3. **Onyx 的优势在企业连接器、权限继承和多入口，而不是知识图谱。**官方文档列出大量持续同步连接器、Slack Bot、Chrome Extension、网站 Widget、引用与企业权限同步；当前仓库还已有单用户定时 Agent 任务实现。[连接器总览](https://docs.onyx.app/admins/connectors/overview) · [Slack Bot](https://docs.onyx.app/overview/onyx_anywhere/slack) · [Chrome Extension](https://docs.onyx.app/overview/onyx_anywhere/chrome_extension) · [定时任务设计与实现说明](https://github.com/onyx-dot-app/onyx/blob/27e26de8aafaa2f7e482c171b4290386af6f381b/docs/craft/features/scheduled-tasks/overview.md#L1-L74)
4. **Khoj 和 AnythingLLM 证明“定时研究/报告”是真需求，但也暴露了边界。**Khoj Automations 能按周期研究并邮件发送结果；AnythingLLM Scheduled Jobs 能定时运行完整 Agent、保存轨迹并发浏览器推送，但后者明确只在单用户模式提供。[Khoj Automations](https://github.com/khoj-ai/khoj/blob/1e30154d1070c7b132f389638c008b490be1481b/documentation/docs/features/automations.md#L1-L10) · [AnythingLLM Scheduled Jobs](https://github.com/Mintplex-Labs/anythingllm-docs/blob/71ea0f950cf7ac2f1002ed4eda7660b0c8ae4148/pages/scheduled-jobs/overview.mdx#L8-L41)
5. **公开分享已常见，访客投稿审核仍是空白。**WeKnora、Onyx 和 AnythingLLM 都提供网站问答入口，NotebookLM 可公开分享整个 Notebook 供访客查询；但本轮没有发现任何对象完整提供“访客上传附件/链接或写内容，但不能直接编辑所有者知识库，提交后进入审核箱”的闭环。[NotebookLM 公共 Notebook](https://support.google.com/notebooklm/answer/16322204?hl=en) · [WeKnora Embed](https://github.com/Tencent/WeKnora/blob/5780affdfc76342ddd0f5cf95b548a1a4d0b2a5a/README.md#L141-L152) · [Onyx Website Widget](https://docs.onyx.app/overview/onyx_anywhere/website_widget) · [AnythingLLM Embedded Widget](https://github.com/Mintplex-Labs/anythingllm-docs/blob/71ea0f950cf7ac2f1002ed4eda7660b0c8ae4148/pages/features/chat-widgets.mdx#L17-L61)
6. **没有对象公开证明具备 FlyWiki 所要求的完整可信写作链路：**不可变 `SourceVersion`、精确 `EvidenceSpan`、结构化 Claim 关系、逐 Claim 引用审计、可回滚知识变更集和不可变发布快照。现有产品普遍止于文档/Chunk/回答引用，或页面级 provenance。

### 1.2 分析推断（不是厂商公开事实）

- FlyWiki 最有价值的差异化不是再做一个“带引用的 RAG Chat”，而是把**来源版本—证据跨度—主张—认知—写作—发布**做成可审计链路，再把追踪结果送入同一条变更审核流程。
- WeKnora 是一期最强的功能对标和交互参考；RAGFlow 是最需要持续监测的技术竞争变量；OpenKB 仍是最贴近 FlyWiki“编译式知识”核心的 Python 底座。
- “访客投稿但不能编辑”“世界知识自动更新而 Belief 只由用户确认”“知道/不知道/新知识/冲突分类推送”是本轮竞品均未完整覆盖的可验证空位。
- Khoj Cloud 的关闭说明集成与多客户端存在显著长尾成本。官方复盘明确提到手工构建数据集成的长尾、云订阅与多客户端造成的规模化困难；这支持 FlyWiki 一期严格控制连接器数量，并把封闭平台放到 Edge Adapter，而不是承诺无限连接器。[Khoj Cloud 关闭公告](https://app.khoj.dev/)

## 2. 评估口径

| 标记 | 含义 |
| --- | --- |
| **● 已产品化** | 官方稳定文档或产品入口明确说明；必要时有源码/测试佐证。 |
| **◐ 部分具备** | 有相邻能力，但粒度、边界或闭环不满足 FlyWiki 定义。 |
| **△ 工程信号** | 当前官方主分支有实现，但尚未在稳定产品文档或 Release 中明确承诺。 |
| **— 未发现** | 在本轮检查的官方文档、README、源码与发布记录中未发现公开证据；不代表绝对不存在。 |

“可信依据”按四层区分：

1. **答案级引用**：回答列出使用过的来源或 Chunk。
2. **页面级溯源**：知识页记录来源文档或 Chunk。
3. **主张级证据**：每条 Claim 指向不可变 SourceVersion 内的精确 EvidenceSpan。
4. **发布级审计**：写作版本逐 Claim 审核引用，并以不可变 Release 发布。

FlyWiki 目标是第 3、4 层；竞品具备第 1、2 层时不能写成“已实现可信写作”。

## 4. Tencent WeKnora

### 4.1 已证实事实

- **定位与目标用户**：官方称其为面向企业级文档理解、语义检索和自主推理的开源知识框架，由日常 RAG 问答、ReAct Agent 和自维护互联 Markdown Wiki 组成。[官方 README](https://github.com/Tencent/WeKnora/blob/5780affdfc76342ddd0f5cf95b548a1a4d0b2a5a/README.md#L47-L55)
- **图谱和 Wiki**：Wiki Mode 会生成互联 Markdown 页面，并在 UI 中提供 Wiki Browser 和知识图谱；检索策略包括 GraphRAG。[版本能力](https://github.com/Tencent/WeKnora/blob/5780affdfc76342ddd0f5cf95b548a1a4d0b2a5a/README.md#L66-L75) · [功能矩阵](https://github.com/Tencent/WeKnora/blob/5780affdfc76342ddd0f5cf95b548a1a4d0b2a5a/README.md#L117-L130)
- **来源与引用**：聊天支持内联引用弹层、References Drawer，并区分网页和知识库来源；Wiki 页面内部保存文档与 Chunk 引用，但公开实现仍主要是页面/Chunk 级溯源。[聊天引用](https://github.com/Tencent/WeKnora/blob/5780affdfc76342ddd0f5cf95b548a1a4d0b2a5a/README.md#L117-L118) · [WikiPage 引用字段](https://github.com/Tencent/WeKnora/blob/5780affdfc76342ddd0f5cf95b548a1a4d0b2a5a/internal/types/wiki_page.go#L207-L224)
- **追踪**：飞书、Notion、语雀和 RSS 支持增量与全量同步。这属于“已知数据源定时同步”，不等同于对开放世界主题做研究、差异归纳和认知更新。[数据源能力](https://github.com/Tencent/WeKnora/blob/5780affdfc76342ddd0f5cf95b548a1a4d0b2a5a/README.md#L125-L130)
- **IM**：官方列出企业微信、飞书/Lark、QQBot、Slack、Telegram、钉钉、Mattermost、微信和云之家；另有微信小程序。[集成矩阵](https://github.com/Tencent/WeKnora/blob/5780affdfc76342ddd0f5cf95b548a1a4d0b2a5a/README.md#L133-L152) · [微信小程序](https://github.com/Tencent/WeKnora/blob/5780affdfc76342ddd0f5cf95b548a1a4d0b2a5a/README.md#L163-L166)
- **浏览器插件**：官方 Chrome Extension 能把选中文字、图片或整页保存为知识条目。[插件说明](https://github.com/Tencent/WeKnora/blob/5780affdfc76342ddd0f5cf95b548a1a4d0b2a5a/README.md#L158-L161)
- **分享**：知识库可跨组织分享，并选择 `viewer` 或 `editor`；后端还以来源 Workspace 权限、组织角色和租户角色共同限制实际能力。这是成员制共享，不是匿名访客投稿。[分享 UI](https://github.com/Tencent/WeKnora/blob/5780affdfc76342ddd0f5cf95b548a1a4d0b2a5a/frontend/src/components/ShareKnowledgeBaseDialog.vue#L63-L72) · [分享权限服务](https://github.com/Tencent/WeKnora/blob/5780affdfc76342ddd0f5cf95b548a1a4d0b2a5a/internal/application/service/kbshare.go#L24-L78)
- **网站入口**：Embed Widget 可把 Agent 放到外部网站；近期版本支持安全令牌交换、限流和会话临时附件。临时附件不等同于写入知识库。[版本记录](https://github.com/Tencent/WeKnora/blob/5780affdfc76342ddd0f5cf95b548a1a4d0b2a5a/README.md#L60-L63)
- **多租户与治理**：Workspace RBAC 是 Owner/Admin/Contributor/Viewer 四级，含逐 KB 所有权、审计日志、多 Workspace 和 scoped API key。[权限能力](https://github.com/Tencent/WeKnora/blob/5780affdfc76342ddd0f5cf95b548a1a4d0b2a5a/README.md#L150-L156)
- **部署与扩展**：本地、Docker、Helm/Kubernetes、私有和离线部署均有官方入口；模型、向量库、对象存储、解析、搜索、IM、REST、CLI、MCP 都有扩展面。[架构与部署](https://github.com/Tencent/WeKnora/blob/5780affdfc76342ddd0f5cf95b548a1a4d0b2a5a/README.md#L98-L103) · [功能矩阵](https://github.com/Tencent/WeKnora/blob/5780affdfc76342ddd0f5cf95b548a1a4d0b2a5a/README.md#L133-L156)
- **许可与价格**：主仓库为 MIT；自托管没有软件许可费。README 提到 WeKnora Cloud，但本轮未发现独立公开金额页。[LICENSE](https://github.com/Tencent/WeKnora/blob/5780affdfc76342ddd0f5cf95b548a1a4d0b2a5a/LICENSE)
- **活跃度**：快照 HEAD `5780aff` 的提交时间为 2026-07-31，内容仍在修复批量重解析失败，显示项目持续开发。[HEAD commit](https://github.com/Tencent/WeKnora/commit/5780affdfc76342ddd0f5cf95b548a1a4d0b2a5a)

### 4.2 未发现与 FlyWiki 差异

- 未发现不可变 SourceVersion、精确页码/坐标/字符范围 EvidenceSpan、逐 Claim 引用覆盖和不可变 KnowledgeRelease。
- 未发现“我知/我不知/世界新知识/冲突”分类后的主动报告推送。
- Embed 附件是会话上下文；跨组织 Editor 能直接编辑。两者都不是 FlyWiki 的“外部访客可投稿，但只能进入 Knowledge Inbox 审核”。
- 后端主体为 Go。其 IM、分享、插件、RBAC 设计值得参考，但不适合作为 FlyWiki Python 统一技术栈的直接依赖。

## 5. RAGFlow

### 5.1 已证实事实

- **定位**：官方定位是融合 RAG 和 Agent 的开源上下文引擎，面向企业规模的数据理解、检索和 Agent 应用。[README](https://github.com/infiniflow/ragflow/blob/776b9371f7f8a7ef44161d5ed01805ceaa0e244d/README.md#L76-L80)
- **文档理解与引用**：官方强调复杂格式解析、可人工查看 Chunk，以及回答中的关键引用和可追踪 citation。[README 功能](https://github.com/infiniflow/ragflow/blob/776b9371f7f8a7ef44161d5ed01805ceaa0e244d/README.md#L113-L140)
- **知识图谱**：从 v0.16 起可在整个 Dataset 跨文件构图，新文件解析时自动更新；但删除相关文件后不会自动更新，必须重建，而且官方文档明确不支持导出图谱。[构图与更新](https://github.com/infiniflow/ragflow/blob/776b9371f7f8a7ef44161d5ed01805ceaa0e244d/docs/guides/dataset/advanced/construct_knowledge_graph.md#L16-L30) · [删除与导出限制](https://github.com/infiniflow/ragflow/blob/776b9371f7f8a7ef44161d5ed01805ceaa0e244d/docs/guides/dataset/advanced/construct_knowledge_graph.md#L89-L105)
- **知识编译工程信号**：当前主分支 `KnowledgeCompiler` 已能将结构、Wiki、Tree、Mindmap、Dataset Navigation 产物转成统一 Chunk 流，并包含租户和数据集作用域；内置模板也已存在。由于稳定 README 和 Release Notes 尚未将其列为正式能力，本文只标为“工程信号”，不标成 GA。[组件接口](https://github.com/infiniflow/ragflow/blob/776b9371f7f8a7ef44161d5ed01805ceaa0e244d/internal/ingestion/component/knowledge_compiler/component.go#L57-L82) · [变体分派](https://github.com/infiniflow/ragflow/blob/776b9371f7f8a7ef44161d5ed01805ceaa0e244d/internal/ingestion/component/knowledge_compiler/component.go#L109-L182)
- **IM**：README 在 2026-06-15 更新项中列出飞书、Discord、Telegram、Line 等；主分支还包含企业微信、WhatsApp、钉钉、QQBot 等 Channel Adapter。[README 更新](https://github.com/infiniflow/ragflow/blob/776b9371f7f8a7ef44161d5ed01805ceaa0e244d/README.md#L89-L101) · [官方 Channels 源码目录](https://github.com/infiniflow/ragflow/tree/776b9371f7f8a7ef44161d5ed01805ceaa0e244d/api/channels)

**可借鉴（推断）**：模板、变量、自动按站点匹配、选区/高亮、离线 Markdown 和可导出配置；FlyWiki 还需补来源快照、权限提示、失败队列和 Inbox 审核。

### 9.3 NotebookLM：可信问答与公共知识分享标杆

- **来源与引用**：支持 PDF、网页、YouTube、音频、Google Drive、图片等；回答带内联 citation，悬停显示原文，点击跳到引用位置。[产品能力](https://support.google.com/notebooklm/answer/16164461?hl=en) · [Citation 行为](https://support.google.com/notebooklm/answer/16179559?hl=en)
- **联网研究**：Fast Research 和 Deep Research 可以搜索网页、生成报告并让用户挑选哪些结果导入为 Source。[新增来源](https://support.google.com/notebooklm/answer/16215270?hl=en)
- **图形输出**：Mind Map 是来源的导航性输出，不是可编辑的实体关系知识图谱。[NotebookLM Help](https://support.google.com/notebooklm/)
- **公共分享**：Notebook 可设置 Anyone with link；访客能读来源、查看产物并提问，但官方明确 Viewer 不能新增自己的 Source 或生成新 Artifact。这非常接近 FlyWiki 只读问答分享，却不具备访客投稿。[公共 Notebook](https://support.google.com/notebooklm/answer/16322204?hl=en)
- **部署与价格**：闭源 Google SaaS，不提供自托管。Standard 可免费使用；更高配额通过 Google AI、Workspace 或 Google Cloud/Enterprise 计划提供，金额和地区相关。[升级说明](https://support.google.com/notebooklm/answer/16213268)

**可借鉴（推断）**：Citation hover → 原文定位、Source 选择器、Chat View 分享、来源和生成 Artifact 分栏；FlyWiki 应额外提供不可变 Release、访客投稿区和审核状态。

## 11. 对 FlyWiki 可行性和产品设计的直接输入

### 11.1 应坚持的差异化

1. **Claim—Evidence 而不是只有回答 Citation**：保留原文版本和精确 locator，TrustedVersion 必须通过 Claim-Citation Audit。
2. **追踪结果进入 Knowledge Inbox**：定时任务不是终点；新内容必须形成差异、冲突、更新、未知和建议 ChangeSet。
3. **Belief 与世界知识分离**：竞品普遍没有这一层。世界知识可以自动编译，用户认知只能提议变更并确认。
4. **分享采用不可变 KnowledgeRelease**：避免共享视图随所有者后台实时变化而不可审计。
5. **访客写入隔离**：Visitor Session 可问答、写作、上传，但所有内容先进入隔离空间和审核箱，绝不直接修改 KB。

### 11.3 必须持续监测的竞争信号

- **RAGFlow KnowledgeCompiler** 是否进入稳定 Release、是否暴露 Wiki UI/导出/增量撤回和来源映射。
- **WeKnora Wiki citation** 是否从页面/Chunk 级升级到 Claim 级，Embed 是否增加持久访客投稿。
- **Onyx Scheduled Tasks** 是否从单用户扩展到团队、事件触发和外部通知。
- **AnythingLLM Scheduled Jobs/Telegram** 是否解除 multi-user 限制，Chrome Extension 是否恢复高频维护。
- **OpenKB** 是否增加数据库存储、多用户、Hook/Plugin 稳定合约；这些变化决定 FlyWiki Adapter 的上游合并策略。
