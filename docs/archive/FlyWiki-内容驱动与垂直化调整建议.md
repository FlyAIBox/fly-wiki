# FlyWiki 内容驱动与垂直化调整建议

> 日期：2026-07-23  
> 文档性质：产品战略诊断与调整建议  
> 参考方法：《个人开发者产品方法论：内容驱动型产品》  
> 核心问题：FlyWiki 是否应该选择多个具有传播属性的垂直领域，以及当前产品需要做哪些调整。

## 一、执行结论

FlyWiki 应该垂直化，但现阶段不应该同时选择多个垂直领域。

当前最合适的策略是：

> **先建设一个公开可传播的 AI Agent 产品研究库，用它吸引用户；再为每个用户建立私有、可持续进化的认知与证据工作区。**

最新版《PRD：FlyWiki 垂直认知顾问》已经选择“AI Agent 与科技产业研究”作为首个方向，这个决策基本正确。下一步不需要继续寻找更多领域，而需要完成三项工作：

1. 将“AI Agent 与科技产业研究”收窄为一个具体用户和高频任务；
2. 把获取首次价值的路径从“先导入并维护知识库”改为“先获得证据包”；
3. 在私人知识库之外增加可搜索、可引用、可分享的公开内容层。

FlyWiki 当前已经具备较完整的价值闭环：

```text
资料进入
    ↓
提取主张与证据
    ↓
维护认知版本
    ↓
生成证据化输出
```

但尚未形成完整的增长闭环。建议补充：

```text
公开研究问题
    ↓
可搜索证据页
    ↓
可分享结论卡
    ↓
体验证据包
    ↓
导入私人资料
    ↓
建立私人认知库
    ↓
持续订阅与复用
```

## 二、当前战略状态

### 2.1 已经做对的部分

最新版垂直 PRD 已经明确：

- 不再把 FlyWiki 定义为通用知识库；
- 不以自动生成更多 Wiki 页面为核心价值；
- 首个垂直领域是 AI Agent 与科技产业研究；
- 首批用户是需要持续研究和输出的个人专业用户；
- 核心交付是认知变化和带正反证据的证据包；
- 先验证专业个人用户，再考虑团队与企业；
- 心理、医疗和投资等高风险领域暂不作为首个产品方向。

这与内容驱动型个人产品的方法基本一致：选择自己拥有内容和任务优势的垂直切口，用可复用内容降低开发、运营和获客成本。

### 2.2 仍然存在的战略冲突

项目中的部分较早文档仍然使用通用定位：

- 《产品可行性报告》仍将产品定义为 API-first 的自进化知识库平台；
- 《PRD：FlyWiki 认知与证据工作台》仍面向多个职业和多种输出任务；
- 《MVP 与验证方案》仍按行业报告、深度文章和产品分析等宽泛任务招募用户；
- 路线图仍同时考虑浏览器扩展、手机 App、研究工作台、企业版和连接器生态。

这些文档并非完全错误，但代表的是不同阶段的产品假设。如果继续并列使用，会产生以下问题：

- 开发时无法确定哪类资料和输出格式优先；
- 用户研究混入具有不同任务和付费动机的人群；
- 对外传播时无法用一个具体结果解释产品；
- 容易优先开发通用基础设施，而不是验证垂直价值；
- 功能边界随着不同用户需求不断扩大。

建议将《PRD：FlyWiki 垂直认知顾问（体验验证版）》设为当前唯一有效的产品基线，其他文档标记为历史方案，或根据垂直定位同步修订。

## 三、是否应该选择多个垂直领域

### 3.1 结论：现在只选择一个

现阶段不建议同时进入多个领域。

多个垂直领域意味着：

- 不同的资料来源和数据结构；
- 不同的用户语言和输出格式；
- 不同的证据质量标准；
- 不同的付费结果；
- 不同的风险和合规边界；
- 不同的获客渠道。

对于个人开发者，这些差异会迅速放大开发与运营成本，并使产品无法形成清晰心智。

首个领域建议确定为：

> **AI Agent 产品机会与竞品研究**

首个目标用户建议确定为：

> **需要持续判断 AI 产品机会并输出文章、方案或产品决策的独立产品经理、AI 创业者和技术内容作者。**

首个核心任务建议确定为：

> **输入一个 AI 产品判断或选题，FlyWiki 从公开资料和用户私有资料中生成包含支持、反驳、限制条件、变化历史和原文定位的产品研究证据包。**

### 3.2 为什么首选这个领域

该方向符合个人开发者产品的主要选择条件：

| 条件 | 适配情况 |
| --- | --- |
| 创始人已有资料与经验 | 已有 AI、Agent、知识库和产品研究资料 |
| 用户存在持续任务 | 产品经理、创业者和内容作者需要持续追踪和输出 |
| 信息变化频率较高 | 新产品、新能力和新商业模式持续出现 |
| 证据需求明确 | 产品判断需要来源、对比、反例与时间变化 |
| 内容可以公开传播 | 大量信息来自公开产品、论文、文档和访谈 |
| 输出容易分享 | 结论、对比、时间线和机会分析适合传播 |
| 合规风险相对较低 | 低于医疗、心理诊断和证券投资建议 |
| 与 FlyWiki 能力一致 | 认知变化、正反证据和版本历史都有直接价值 |

### 3.3 先扩任务，不扩领域

第一阶段可以在同一领域内逐步增加相邻任务：

1. AI 产品机会判断；
2. 竞品和差异化分析；
3. Agent 技术选型；
4. 商业模式分析；
5. 能力商品化与壁垒判断；
6. 趋势和关键变化追踪；
7. 文章、方案与决策证据包。

这些任务共享相似的目标用户、资料来源、证据标准和产品模型，扩展成本远低于进入全新领域。

### 3.4 何时可以扩展新领域

建议同时达到以下条件后再考虑第二个垂直领域：

- 至少 10 个公开研究页面持续获得搜索或分享流量；
- 至少 5 名非熟人用户完成真实研究任务；
- 至少 3 名用户真实付费；
- 至少 2 名用户完成第二次任务或主动续费；
- 公开内容能够稳定转化为产品体验；
- 新增一个问题页或研究模板的边际成本明显下降；
- 已经证明正反证据包比普通搜索或 RAG 更有价值。

第二个领域应与第一个领域共享尽可能多的资料、用户或工作流，而不应直接跳到心理、投资等高风险领域。

## 四、“自带传播属性”应该如何理解

### 4.1 垂直领域不会自动产生传播

选择热门垂直领域不等于产品天然能够传播。传播属性来自产品输出是否满足以下条件：

- 回答用户本来就在搜索的问题；
- 结论具体，能够被引用；
- 包含数据、证据或可验证来源；
- 有明确的正反观点和信息增量；
- 可以生成独立链接；
- 适合转发给同事、读者或决策参与者；
- 随新信息进入而持续更新；
- 分享后能够自然引导新用户体验产品。

因此，FlyWiki 不能只建设私人知识库，还要把一部分公共研究结果产品化。

### 4.2 私人知识库天然不利于传播

私人知识库通常包含：

- 用户未公开的文档；
- 私人笔记和判断；
- 内部产品方案；
- 尚未发布的文章；
- 私有来源和引用；
- 用户的历史认知版本。

这些内容不能被搜索引擎收录，用户也很少愿意分享完整资料库。因此，仅依赖私人知识管理无法形成稳定的内容增长渠道。

### 4.3 FlyWiki 需要公共与私人双层结构

#### 公共研究层

允许被搜索、引用和分享：

- AI Agent 产品档案；
- 产品能力和商业模式对比；
- 某个产品判断的正反证据页；
- 技术或商业变化时间线；
- 每周认知变化简报；
- 垂直赛道机会地图；
- 公开来源的证据卡片；
- 带原文定位的研究结论。

#### 私人认知层

默认仅用户本人可访问：

- 用户上传的私有文档；
- 用户自己的判断和批注；
- 内部产品与竞争策略；
- 未发布文章或方案；
- 私有证据和引用；
- 用户确认的结论版本历史。

双层结构的转化路径为：

```text
用户通过搜索或社交媒体发现公开证据页
        ↓
阅读当前结论、正反证据和原文
        ↓
复制该研究任务到自己的工作区
        ↓
加入自己的私有资料
        ↓
生成个性化证据包
        ↓
订阅持续变化或购买付费能力
```

## 五、进一步收窄首个产品切口

“AI Agent 与科技产业研究”仍然包含过多任务，例如：

- 阅读和总结论文；
- 跟踪产品动态；
- 进行技术选型；
- 分析商业机会；
- 判断产品壁垒；
- 写行业文章；
- 做竞品和市场分析。

这些任务对应的资料、证据标准和最终交付物并不完全相同。

建议首版将用户、任务和交付物固定下来。

### 5.1 用户

- 独立产品经理；
- AI 创业者；
- 技术内容作者；
- 高频进行 AI 产品研究的顾问或分析人员。

### 5.2 任务

用户输入一个与 AI Agent 产品有关的判断、问题或文章选题。

例如：

- Agent Skill 是否会成为新的产品分发渠道？
- 哪些 AI Agent 能力正在快速商品化？
- 某款 AI 产品真正的差异化来自哪里？
- 哪些垂直 Agent 具有高频任务和明确付费结果？
- 某个产品方向最近出现了哪些支持或反对的新证据？

### 5.3 交付物

统一输出一份产品研究证据包：

1. 当前结论；
2. 可验证的子断言；
3. 支持证据；
4. 反方证据；
5. 限制条件；
6. 证据缺口；
7. 最近发生的变化；
8. 原文定位与来源；
9. 建议继续验证的问题；
10. 用户采用或放弃结论的反馈入口。

统一交付物能够降低开发范围，也便于对比不同任务的效果和形成公开内容模板。

## 六、首次价值路径需要调整

### 6.1 当前路径的问题

当前 MVP 假设用户拥有并导入大量历史资料，然后完成主张抽取、证据关系、主题编译、认知确认，最终才获得输出证据包。

这条路径需要用户：

- 导入约 100 条资料；
- 等待解析和主题编译；
- 理解多个抽象概念；
- 处理认知变化卡；
- 维护个人主题；
- 最后才能看到核心结果。

对于尚未建立信任的新用户，这一成本过高。用户还没有感受到价值，就先承担了数据迁移和知识维护负担。

### 6.2 建议的新路径

首个体验应改为：

```text
用户选择一个预设问题或输入产品判断
        ↓
直接调用 FlyWiki 已有的公共 AI 研究资料
        ↓
在数分钟内生成第一份证据包
        ↓
用户确认结果有价值
        ↓
再邀请用户导入私人资料
        ↓
生成个性化证据包并保存认知版本
```

产品应从“先建立知识库，再获得价值”调整为：

> **先用公共垂直知识库交付价值，再邀请用户建立私人知识库。**

### 6.3 功能优先级

建议首版优先级调整为：

1. 输出与证据台；
2. 当前结论与正反证据；
3. 公开分享页；
4. 原文定位和引用；
5. 变化卡；
6. 私人认知版本；
7. 完整知识库管理；
8. 复杂连接器和多端客户端。

“认知收件箱”和“主题维护”可以先作为后台能力，不应成为首次使用的必经步骤。

## 七、传播型内容矩阵

book2skills 使用“书籍 × 行业 × 用户问题”形成内容矩阵。FlyWiki 可以使用：

> **产品或技术 × 研究任务 × 用户问题**

例如：

| 产品或技术 | 研究任务 | 页面问题 |
| --- | --- | --- |
| Agent Skill | 渠道判断 | Agent Skill 会不会成为新的产品分发渠道？ |
| AI 编程 Agent | 能力比较 | 哪些能力已经商品化，哪些仍可能形成壁垒？ |
| MCP | 商业机会 | MCP 生态中有哪些可以独立收费的产品？ |
| 垂直 Agent | 场景判断 | 哪些领域具有高频任务和明确付费结果？ |
| 某个 AI 产品 | 竞品分析 | 差异化来自模型、数据、工作流还是渠道？ |
| Agent 框架 | 技术选型 | 不同框架分别适合什么产品和团队？ |

每个公开页面采用统一结构：

1. 问题；
2. 当前结论；
3. 支持证据；
4. 反方证据；
5. 限制条件；
6. 最近变化；
7. 原文引用；
8. 未解决问题；
9. 相关研究页面；
10. “用我的资料重新分析”入口。

同一套主张与证据引擎由此同时承担两种职责：

- 为用户生成私人研究结果；
- 为 FlyWiki 生成公开内容与获客页面。

## 八、产品结构调整对照

| 当前设计 | 建议调整 |
| --- | --- |
| 自进化知识库 | AI Agent 产品研究与证据顾问 |
| 先导入大量资料 | 先使用预装公共资料获得结果 |
| 三个核心界面并列 | 首先突出输出与证据台 |
| 用户维护多个主题 Wiki | 用户先选择一个 Mission 和少量持续问题 |
| 输出主要是私人 Markdown | 同时支持公开证据页和私人证据包 |
| 只验证证据质量和付费 | 增加搜索、分享和公开页转化指标 |
| 面向多类知识工作者 | 首先面向独立产品经理、AI 创业者和技术作者 |
| 同时探索多个领域 | 先扩展同一领域内的相邻任务 |
| 自动生成更多知识 | 持续减少用户需要处理的信息 |
| 以摄取和知识组织为入口 | 以真实产品判断和证据输出为入口 |

## 九、建议增加的增长指标

当前指标重点是证据准确率、引用定位、时间节省和持续使用。这些指标应继续保留，同时增加内容增长指标。

### 9.1 公开内容指标

- 公开研究页面数量；
- 搜索引擎收录率；
- 自然搜索曝光和点击；
- 页面被分享的次数；
- 外部引用或反向链接；
- 用户从一个证据页继续访问相关页面的比例。

### 9.2 产品转化指标

- 公开页面到“生成我的证据包”的点击率；
- 匿名体验到注册工作区的转化率；
- 使用公共资料后主动导入私人资料的比例；
- 首次生成证据包所需时间；
- 证据包导出或分享率。

### 9.3 留存与商业指标

- 用户是否完成第二个研究任务；
- 是否订阅某个持续问题的变化；
- 私人资料在后续任务中的复用率；
- 单次证据包付费率；
- 订阅和续费率；
- 每个任务的模型与人工成本。

## 十、建议的四周调整计划

### 第一周：统一定位与选题

- 将垂直 PRD 设为唯一有效产品基线；
- 明确首个用户是独立产品经理、AI 创业者和技术作者；
- 明确首个任务是 AI Agent 产品判断；
- 收集 10 个真实、高频、适合公开传播的问题；
- 确定统一的证据包结构。

### 第二周：建立公共资料与首个体验

- 从现有资料中选择一批可公开引用的 AI Agent 内容；
- 建立最小主张、证据和来源结构；
- 用户无需导入资料即可输入一个问题；
- 在数分钟内生成包含正反证据的结果；
- 保留所有关键引用的原文定位。

### 第三周：生成公开研究页面

- 发布首批 5 至 10 个公开问题页；
- 每页包含当前结论、正反证据、限制和来源；
- 增加相关问题和主题内链；
- 提供“复制到我的研究工作区”入口；
- 生成适合社交媒体分享的结论卡片。

### 第四周：验证价值与增长

- 邀请至少 5 名非熟人用户完成真实任务；
- 对比普通搜索、普通 RAG 与 FlyWiki 证据包；
- 记录首次结果时间和证据采用率；
- 观察公开页面的访问、分享和产品转化；
- 测试单次付费或四周研究陪跑；
- 根据第二次使用和真实支付决定是否继续。

## 十一、暂不建议进行的工作

在首个垂直任务通过验证前，不建议优先开发：

- 多个垂直领域模板；
- 完整手机 App；
- 全量浏览器收藏同步；
- 多种企业连接器；
- 复杂的全局知识图界面；
- 大型团队权限和审计系统；
- 自动生成整篇行业报告；
- 心理咨询或投资建议功能；
- 面向任意知识工作者的通用工作台。

这些能力可能有长期价值，但不能优先证明首个垂直任务是否成立。

## 十二、最终产品判断

FlyWiki 不应该被定义为“支持多个垂直领域的自进化知识库”。更适合当前阶段的定义是：

> **FlyWiki 是一个面向 AI Agent 产品研究的证据顾问：持续把公开和私人资料压缩为认知变化，在用户进行产品判断、写作或决策时，生成带正反证据和原文定位的研究结果。**

它的产品结构应由两部分组成：

1. **公开研究与内容引擎**：负责被搜索、被引用、被分享和获客；
2. **私人认知与证据工作区**：负责个性化、数据积累、重复使用和付费。

当前最重要的工作不是增加垂直领域，而是证明：

- 一个公开研究问题能否带来用户；
- 一份证据包能否快速交付价值；
- 用户是否愿意加入自己的资料；
- 资料和认知是否会在第二次任务中被复用；
- 用户是否愿意为持续研究与私人工作区付费。

只有这个闭环成立后，扩展第二个垂直领域才会带来规模效应，而不是增加新的开发和运营负担。
