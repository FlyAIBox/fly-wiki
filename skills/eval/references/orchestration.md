# 两层编排:规划循环与执行循环

本页把经过大规模仿真验证的两层编排方式移植给本技能:**规划层**决定「这个人现在要什么」,**执行层**把一个语义意图落地成若干真实动作。子代理执行任何 case 都按本页循环推进;落盘与验真合同见 `trace-evidence.md`。

## 0. 分层总则

- **规划层 = persona 在想什么**:读观察 → 想 → 发出少量语义动作。绝不直接描述点按坐标或命令细节。
- **执行层 = 动作怎么真实落地**:接到一个语义意图(「打开设置看版本号」),用真实入口分若干子步办成或办不成,回报结果。
- trace 的每个 step 对应**规划层一步**;执行层子步逐条记进该 step 的 `operates` 执行证据(合同见 `trace-evidence.md`),完整原始输出与宿主日志落 `runner-logs/`。
- 两层可以由同一个子代理承担(多数宿主如此),但**循环纪律分开遵守**:先按规划层想清楚要什么,再进入执行子循环落地,落地结果作为下一个规划步的观察。

## 1. 规划步循环(每个 trace step 走一遍)

1. **观察**:读上一步的真实结果(执行回报、页面/屏幕现状、收到的消息)。
2. **思考**:以 persona 的知识和判断方式决定下一步;写成 trace 的 `thought`(简短、可公开)。
3. **动作(稀疏为默认)**:每步只从这个词表里选,多数步只发一个动作:
   - `operate`——把一个语义意图交给执行层;
   - `speak`——公开表达(写进该步的 `say`);
   - `done`——声称办成(必须过第 3 节的终态闸);
   - `give_up`——自然放弃,必须写出这个人现实中会放弃的理由。
4. **落账**:动作与执行结果写入该 step 的 `do` / `say` / `observation`。

**operate 命令三律**:语义化(说要什么,不说怎么点)、确定性(执行侧无需再猜意图)、几步内可完成。一个意图若一个子步就完成,说明拆得太细;若顶着子步上限还没完,说明拆得太粗——回到规划层把它拆小。

**长对话防漂移**:步数多时把早期历史折叠成摘要、近期保全原文;每步重新锚定「你是谁、在办什么事、还剩多少步预算」。persona 记忆里与当前处境相关的片段优先带上,不相关的省略。

## 2. 执行子循环(落地一个 operate 意图)

1. **观察现场**:截图、页面、命令输出——用真实入口能看到的东西,不靠记忆。
2. **选动作并执行**:一次可连发多个不改变画面的小动作;**会切换画面的动作(点击跳转、返回、提交)只能放在最后**,执行后必须重新观察再决定。
3. **验证效果**:对比动作前后的观察,优先取轻信号(命令退出码、页面可见文本变没变);`operates[].shot` 是留档证据,不必每张都读回上下文,关键节点(收口自核、换路决策)才细看画面。没有任何变化 = 动作未生效,**不要原样重复**,换目标或换方法。
4. **无进展熔断**:连续约 3 轮动作后现场无变化,停止这个意图,如实回报「未能完成 + 卡在哪」。
5. **子步预算**:单个意图默认十来个子步、几十步封顶;耗尽即回报未完成,不无限重试。
6. **收口回传**:意图结束时产出一句结果摘要(已完成/未能完成 + 关键现场),它就是下一个规划步的观察;子步逐条写进该 step 的 `operates`(GUI 动作配操作后截图 `shot`,shell 命令 `do` 写字面命令、`output` 放输出关键片段),步末画面进 `shots`,完整输出留 runner-log。

**完成自核(两个方向都守)**:宣告完成前,必须在**当前观察**里逐项核实目标状态——填的值、改的内容真的落对了才算,不凭意图或记忆宣告;反过来,一旦观察已核实到位就立即收口,不为求稳反复观察空转到预算上限。

## 3. done 终态闸

子代理声称 `done` 前,对照 scenario 的 `closure.success` 逐条核验:每个成功条件都要有**当前可指认的观察证据**(截图、输出、页面状态)。核不过就不许 done——要么继续,要么如实转为 `abandoned`/`timeout`。主代理复核 trace 时按同一判据把关:outcome 声称办成但 steps 里找不到证据的 case 视为不一致,按 `trace-evidence.md` 作废重跑。

落 trace 时动作词与终态的对应:`done` → `status="succeeded"`、`give_up` → `"abandoned"`、规划步预算耗尽 → `"timeout"`;`"error"` 只留给工具/环境自身故障(`execution.md` §4)。status 只有这四个枚举,不要把 done/give_up 这类动作词直接写进 status。

## 4. 多 case 编排(本地一律隔离)

- **case 彼此隔离**:每个 case 独立子代理、独立状态副本,互不知晓;彼此无共享可变状态才并行,并行数量以宿主资源为限(几个为宜),其余排队串行——串行不损失信号。
- **多人耦合协作不在本地跑**:同组多人经共享介质实时互动是平台引擎的执行形态,本技能不在本地模拟;本地 Methodology 一律扁平的单人 cases。用户确要多人协作仿真时如实说明这超出本技能的本地形态;显式接平台后才按 `cli.md` 读取平台 groups 合同。

## 5. 预算与失败语义速查

| 层 | 预算 | 耗尽时 |
|---|---|---|
| 规划层 | scenario `max_turns` / methodology `max_steps` | 按现场如实记 `timeout` |
| 执行层 | 单意图子步预算(默认十来步,几十步封顶) | 回报「未能完成」,规划层决定换路或放弃 |

执行层「未能完成」不等于 case 失败——它只是这个人此路不通的真实经历,规划层可以换路、求助或放弃;哪种都是有效信号。工具/环境自身故障才记 `error`(见 `execution.md` §4)。
