# Agent / Model 目标：让用户带着真事来对话

> 仅当 primary surface 是 `agent` 或 `model` 时读取本页。接入界面可能是网页、终端或 API；那只是 runtime，不能把目标误判成 web / cli。

## 人与任务

人物差异重点放在两处：他对同类 Agent 的预期，以及他愿意交出多少上下文。把这些差异写成可召回经历：

- 他在哪一年用过哪个具名 Agent，曾经办成或没办成什么；
- 哪次自信错误没有被他当场发现，决定这次是否验证；
- 他自己写过、维护过或审核过什么，决定能看懂多深；
- 他通常只给一句要求，还是会提供完整材料并来回协作。

Scenario 给人物手上的真实事情与真实材料，例如修一个具体 bug、整理一份真实输入、作出领域判断或完成一段工作流。不要写“帮我测试这个 Agent”，也不要把 rubric、预期失败或理想答案塞进任务。通常给 4–10 轮；真人不会无限追问。

## Packet 与隔离

Packet 给实际接入方式、人物自己的材料、自然任务、往返预算，并明确：**会话必须全新无历史**。不能继承主代理与被测 Agent 的旧会话、上轮反馈、隐藏系统上下文或示范答案。

Local Use 通常为零，因为交互本身就是对话；只有人物现实中本来拥有的周边材料或能力才可注入，且不能替被测 Agent 完成任务。若实际通过网页入口交互，按 SKILL 的 runtime 路由额外加载浏览器合同，但目标仍是对话质量。

## 证据与判读

- 每轮人物说了什么写进 `say`，被测 Agent 回了什么原样写进 `observation`；不能只保留最后答案。
- 被测 Agent 调了什么工具、改了什么文件或暴露了什么可见状态，如实留在该轮观察与 runner log。
- 记录人物是否补上下文、纠正、追问、核验、接受、误信或放弃；预期差通常藏在中间几轮。
- 不只判断答案对不对，还要判断人物能否察觉它错了。不可察觉的错误与能被用户及时发现的错误风险不同。

主代理不能替被测 Agent 补答案、解释它“本来想说什么”或用源码证明它会做。复验必须用新会话；历史上下文中的成功不能外推成首次使用能力。

## 常见失真

- 用带历史的会话，把上文当成产品能力。
- 把分析问题或 rubric 发给人物，诱导他照着找问题。
- 只统计正确率，忽略信任、核验成本和错误可察觉性。
- 执行层替人物提供他现实中不会给出的完整上下文。
