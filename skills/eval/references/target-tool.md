# Skill / CLI 目标：装进真实工作流里运行

> 仅当 primary surface 是 `skill` 或 `cli` 时读取本页。

## 人与任务

人物差异来自技术水平和已有工作流，而不只是职位：

- 当前使用哪些具名工具与版本；
- 上次从什么迁到什么、为什么换、迁移哪里最疼；
- 被哪个 quickstart 或依赖坑过，决定是否照说明继续；
- 机器上本来有什么，决定会遇到哪类环境问题。

Scenario 给一件人物手上的真实任务，而不是“试试这个工具”。新手、熟手、已有替代品的人可以面对不同自然任务与放弃阈值；通常给 10–20 个规划步，安装和摸索本来就是这一族的重要行为。

## Packet 与隔离

Packet 给隔离的 cwd、干净配置与依赖、公开安装/使用说明、真实输入和自然完成条件。子代理只能看公开材料；不能读仓库源码、继承主代理已经装好的依赖或复用上一 case 的配置。

每个 case 使用显式 `mktemp -d` 等独立目录。环境预置、构建和服务启动属于 preflight，不写成用户行为。Local Use 可以承载人物现实中已有、且不在验证焦点上的周边能力；绝不能包装正在验证的安装、首次配置或 CLI 命令本身。

## 证据与判读

- 从安装到首次成功的每条真实命令、stdout/stderr、退出码逐条写入 `operates`。
- 第一次成功之前的所有失败都保留；它们是上手成本，不是噪声。
- Shell 动作就写字面命令，不能叙述成“点击了界面”。完整输出留 runner log，trace 放足以复核的片段。
- 记录人物何时查说明、换方法、修改配置、回到旧工具或自然放弃。

读源码不能代替真装真跑；主代理环境里“已经能运行”也不能证明干净用户能上手。若唯一可用入口超出人物现实能力，应让他真实受阻，不能由执行模型偷偷跨过门槛。

## 常见失真

- 继承主机缓存、配置或依赖，抹掉首次使用成本。
- 用 Local Use 直接返回被测 CLI 的结果。
- 跳过安装失败，只保存最后一次成功。
- 把一个空泛 demo 当成用户真实工作。
