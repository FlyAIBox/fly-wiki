# 文档 / 图片目标：按最终成品真实阅读和使用

> 仅当 primary surface 是 `document` 或 `image` 时读取本页。PPT、Keynote、Slides 与投屏稿都映射为 `document`，不新增 presentation surface。

## 人与任务

成品类的使用轨让人物读它、看它，并据此完成真实理解、判断或转手使用。人物差异重点写成经历：

- 背景知识和术语门槛；
- 三十秒扫读还是十分钟细看；
- 看过、讲过或制作过哪些同类材料；
- 上次误读同类成品后作了什么错误决定；
- 上次把别人材料拿去投屏、发客户或并入自己材料时，是原样使用还是重新做了一版。

至少一个使用轨人物必须真的要把成品转手拿到别人面前；“能不能原样用”是他的自然决定，不是审稿提示。只为读懂而来的阵容无法给出发布完成度的行为证据。

## Packet 与真实入口

Packet 给最终交付文件或渲染图、真实观看尺寸、使用场合、人物要作的判断，并明确：**他只有这份成品，没有作者现场讲解**。源码、对象树、alt 文本和生成代码都不是评价对象——不进 case 可见范围，也不能替代最终形态。

按交付形态取像素：

- **图片成品**（架构图、示意图、海报这类以图片文件交付的）：评价对象就是那份图片文件，直接看它。它怎么来的不改变这一条——模型直接生成或代码渲染兜底皆然；人物看的、evidence 存的、指纹盖的都是同一张图。
- **网页成品**（本来就以网页交付的单页报告等）：按真实观看尺寸截图再看，如 `npx playwright screenshot --viewport-size=1440,900 file:///abs/path/report.html shot.png`。
- **PDF** 逐页转图再看；**PPT/演示文稿**必须提供整套缩略总览、逐页真实比例渲染和播放顺序。
- **Markdown** 版式重要时先渲染；直接读源文本只能算内容检查，结论里如实说明。

图片先在真实投放尺寸观看，再按人物自然需要放大。Local Use 为零，只有理解与使用，没有可封装的操作捷径。

## 使用轨证据

- 每步实际看到的成品画面写入 `shots`；没有画面证据就不能声称看过视觉成品。
- 保留第一眼复述、阅读顺序、误读、遗漏、回看、放大、判断与原话。
- 记录转手使用者是否原样采用、裁剪、加注、重排或重做；最后办成不抹掉返工成本。
- 使用轨通常 3–6 步；重点是看得真，不是机械增加步骤。

纯文字文档且本次决定完全不涉及版式或视觉呈现时，只运行本页的使用轨即可。图片，以及视觉表达承载信息、或用户要求“好看 / 专业 / 可发布 / 可演示”的文档与 PPT，还必须按 SKILL 的条件路由叠加独立设计评审合同。

## 常见失真

- 只读 Markdown、PPT 对象树或生成代码，就说看过成品。
- 只在大屏原尺寸观看，漏掉实际投放尺寸的可读性。
- 把“元素都在”当成“人物理解正确”。
- 在使用轨 scenario 里写“留意排版好不好”，把自然用户变成审稿人。
- 人物自己返工后完成，却把返工记成个人习惯而仍判原样可用。
