# eval 引导模式(可选)

本页是引导模式的配置合同。**默认不启用**——eval 仍自主、少打扰,信息足够就直接推进。仅当用户要求参与配置、或你提议引导且用户接受时,按本页走。引导只发生在**你(主代理)与用户之间**,不改变后续 planning / execution / trace 合同或 CLI 姿势。

## 1. 何时进入 / 何时退出

进入引导:
- 用户显式表达:"引导我 / 一步步问我 / 带我配一下 / 让我参与配置 / guided";
- 或需求特别模糊、且用户没说"自主 / 别问我"时,**提议一次**"要不要我引导你把这次模拟配一下?"。用户拒绝即回默认自主流程,不再追问。

随时退出(快速通道):引导过程中用户任何一句"按推荐来 / 别问了 / 你定"→ 立即停止提问,用当前推荐默认跑完剩余配置。

## 2. 开场先告知运行位置

进入引导后先说明两件事(执行在哪、结果去哪):

> 本次模拟在**你的本地**运行(你的机器出算力、浏览器/shell,子代理扮演各类用户),不提交服务端执行;**结果默认只留在你本地**——session、逐步截图与命令输出都在 `~/.mirasim/eval/sessions/` 下,跑完我把这次记录的查看链接直接给你(在 mirasim 里跑就是本地页面的直链,裸 CLI 下用 `mirasim eval` 打开)。**想让我同时留档到 mirofish 平台就说一声**,我才会接平台上传(敏感信息会脱敏、含凭据的截图不传)。

不展开,但两点要区分清楚:**本地运行 ≠ 一定会写 mirofish**——仿真在本地跑,平台留档默认关闭(opt-in,用户明确要才做),不要主动追问要不要传。服务端大规模真端仿真(execute_by=platform)本期不支持;用户若追问,诚实说"当前只在本地跑",不做转介。

## 3. 逐步小问:决策点(内容锚点组一次亮出,主动打断约 3-4 次)

先按产品理解在后台把整套配置的推荐默认想好(这步不打断用户),再按下表顺序逐点征询。每点给**推荐默认 + 一句为什么**,映射到 methodology 字段:

| # | 决策点 | 写入的配置(与 planning.md §2-3 一致) | 推荐默认来源 |
|---|---|---|---|
| 1 | 验证问题 & 分析口径 & 走多深 | `meta.analysis.questions` + `dimensions`(按哪些维度看行为差异) + `deliverable`(反馈形态:语义反馈 / 量化) + 授权深度(看看 / 优化 / 持续改进) | 用户原话意图 + 产品理解 |
| 2 | **(内容锚点)亮出共享开场情境,邀请用户核对/改** | `world.situation`(所有 case 共享的客观开场背景:被测物是什么、在哪、预置了什么) | 产品理解 + 目标入口的客观事实 |
| 3 | **(内容锚点)亮出每个 persona 的人话摘要(谁 / 用过做过什么 / 因此形成了什么判断标准),邀请提修改方向** + 定几个视角 | 每个 persona 的 `memory.episodes` → `skills` → `profile`(按 cast.md 倒序建构)→ `cases[].persona_id` | 产品目标受众(默认全部本地新造;仅用户要求接平台时才 `mirofish grep` 复用库存) |
| 4 | **(内容锚点)亮出每个 scenario 的人话摘要(要办的事 / 成功·放弃条件),邀请提修改方向** | 每个 scenario 的 `goal`/`env`/`closure` 要点 → `cases[].scenario` | 验证问题 + 各 persona 的处境 |
| 5 | 规模 & 真实入口 | case 数、`world.closure.max_steps` / scenario `max_turns`、`runtime`(start_url / cwd / mobile) | 不确定性大小定视角数;入口从目标推断 |
| 6 | 要不要量化 | `meta.measure`(默认空 / 不量化) | eval 默认语义化反馈;仅比较版本 / 卡门槛时才建议量化 |

**输出语言不占一个决策点,但要在开场那一句里说出来。** 按 SKILL.md「先定这一轮说什么语言」判定后(默认跟用户说话的语言),连同运行位置一起告知:「这轮的 persona、轨迹和报告都用 <语言> 写,想换直接说」。它属于始终暴露、可就地改的运行配置,不值得单独打断一次——但也不能不告而定,因为它决定了用户最后读到的每一份产出。

### 决策点 2/3/4 是内容锚点组(必做,不被完全跳过)

共享情境(`world.situation`)、每个 persona、每个 scenario 决定"从什么背景出发、测的是谁、办什么事",是用户最该知情、最该有发言权的部分。**默认(非引导)的 eval 会自造它们、用户看不到,往往跑完才知道测了什么。** 引导模式必须在派发子代理前,把**共享情境 + 每个 persona + 每个 scenario 各压成一段人话摘要,一次性一起亮给用户,并邀请提修改方向**——不贴完整 JSON、不逐字段问,整体确认或指方向即可(这三样合起来算**一次**内容确认、只打断一次,不算膨胀)。**即使用户走"按推荐来"快速通道,这组内容摘要也要先亮一眼再默采**:其余决策点可静默用推荐默认,唯独这一组不静默略过。

⚠️ 铁律:`world.situation` 与 persona/scenario 属**轨迹层**,只写客观事实与自然处境,**绝不注入评测口径**(不写"留意 X 好不好 / 判断值不值得用 / 找茬")。让用户核对情境时也守这条——情境只描述"被测物客观是什么",不描述"该测出什么"。

摘要格式(每条一两句,让用户一眼看懂、好提意见)。**persona 摘要必须带两个具名锚点**——他用过什么 / 做过什么 / 被什么坑过,不要只给身份标签。只给标签的摘要用户看不出人跟人的差别,也提不出修改方向:

- 共享情境:「MiroFish 是个舆论推演演示,跑在本地 localhost:3100,预置了'某高校撤销处分引发舆情'的案例,免登录、中英文可切」
- persona:「Marcus,危机公关顾问,十二年;自己维护一套 Excel 舆情跟踪表,2021 年被某个'AI 舆情监测'SaaS 的情绪曲线误导过一次,从此看任何预测先找它的数据来源」
- scenario:「客户昨晚出了处分撤销的事,明早九点要交处置建议;他手上只有几张截图和一份时间线,想先看看这东西能不能替他把走势推一遍。拿到能写进方案的东西=成功;十分钟内看不出结论从哪来就回去手写=放弃」

persona 摘要里写他对**别的**东西的既有判断(那是人设),不写他对被测物的态度(那是自证预言)。scenario 摘要写他为什么是今天来办这件事,不写「判断值不值得用」。

用户提了修改方向就改对应情境/persona/scenario 再亮一次确认;认可(或未响应)即定稿。定稿的完整资产按 [cast.md](cast.md) 的密度写(摘要只是给用户看的投影,不是资产本体——别把摘要当 persona 落库)。

**其余配置**(persona 三件套细节、Local Use、隔离方式、`closure` 细节)不主动问,走推荐默认;但整套配置始终对用户暴露——用户任何时候说"我还想改 X"就地调,并按需回到受影响的决策点重走。

每点的问法模板(自包含、不追问链):

> 【决策点名】我的推荐是 <推荐默认>,因为 <一句理由>。要照这个来,还是改一下?(也可以直接说"按推荐来"我就把剩下的一起定了)

## 4. 防拖太长(核心,必须遵守)

- 每点**推荐默认先行**,问题一次给全,不连环追问。
- **未响应即默采**:用户不作答、或说"稍后 / 你定"→ 采纳推荐默认继续。
- **一键全默认**:"按推荐来 / 别问了"→ 终止全部提问,用推荐默认直接跑完配置、进入运行。
- **工具适配**:
  - 有交互提问工具(mirasim `im_ask_user`、宿主的 AskUserQuestion 等)→ 逐点用它问,每问内建推荐默认;
  - 没有 → 把这 4-5 点的推荐默认**一次性列出、结束回合等用户一句确认**(不逐条阻塞、不空转)。
- **诚实边界**:真正"超时自动继续"依赖宿主定时能力,本合同只表达"未响应 / 明确弃权即默采推荐",不承诺无宿主支持下的自动计时。

## 5. 边界:引导不改动这些

- 子代理 packet 反污染合同(不含 analysis / measure / 其他 case / 历史 feedback / 修改意图)——引导是主代理与用户之间,与子代理隔离无关。
- `planning.md` 的资产合同与 `execution.md` / `trace-evidence.md` 的执行证据合同。
- CLI 默认不用 / 平台留档 opt-in 的姿势;引导只涉及本地配置决策,不把"要不要接平台"变成一个必问的决策点。
- 未进入引导时,eval 默认自主行为一切照旧。

## 6. 收尾:回到主流程

征询完成(或被快速通道跳过)后,把定下的配置按 `planning.md` 写进 methodology(`meta` / `cases` / `world`)与 `case-index.json`;真正派发时再加载 `execution.md`、`orchestration.md` 与 `trace-evidence.md`。引导只是在“把请求变成一次外部使用”阶段插入配置协商,不改变其后的执行合同。
