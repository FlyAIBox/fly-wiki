# Web 目标：让用户在真实网页里办事

> 仅当本轮验证问题的 primary surface 是 `web` 时读取本页。若只是借网页与一个 Agent 对话，primary surface 仍是 `agent`，不要加载本页；浏览器只是 runtime。

## 人与任务

子代理是带着真实目的来的用户，不是 QA 或 UX reviewer。差异重点写进 `memory.episodes`：

- 他过去在哪个具名产品里找过同类功能、先会去哪里找；
- 哪个界面曾经骗过他，决定他信不信页面上的话；
- 他手上的时间压力与上次怎样放弃，决定他愿意试几次。

Scenario 给一件自然任务，例如完成首次关键流程、修改已有设置、带着自己的数据作决定或处理一次异常。只写目的、客观处境、可观察的成功与自然放弃条件，不写按钮路径、疑似缺陷、正确答案或“检查体验”。通常给 8–15 个规划步；真人不会在同一页面上机械试二十次。

## Packet 与真实入口

Packet 只给起始 URL、账号初态（全新访客 / 已登录测试账号 / 有历史数据）、窗口尺寸、自然任务和一句硬约束：**只能看这个界面，不能读源码或仓库**。网页 case 的 runtime 必须另外按 SKILL 路由加载浏览器驱动合同。

界面初态属于 preflight：登录、造数据或直达任务起点不能混进用户 trace。每个 case 使用独立账号、浏览器上下文和状态副本；不能复用上一位用户的 cookies、历史或学习结果。

Local Use 默认不用。已登录 profile、start URL 与预置数据是初态，不是 Use；用户本来应该在界面里完成的路径绝不能包成命令或 API 后门。

## 证据与判读

- 每次点击、输入、导航后的画面进对应 `operates[].shot`，规划步末画面进 `shots`。
- 动作按用户能看见的文字记录，不写选择器或“第几个按钮”。
- 关键界面文案在 `observation` 原样摘录；“页面写了”不等于用户看懂了，只认人物自己的复述与决定。
- 记录首选路径、犹豫、回看、绕路、误解、求助、放弃与最终状态。办成但很费劲仍是信号。

没有真浏览器交互时，只能把结论降为内容检查；读 HTML、源码或静态 DOM 不能证明交互体验。执行代理点错、定位失效或浏览器故障属于装置问题，不能算成产品导致的用户失败。

## 常见失真

- 按序号或坐标乱点，再把错误归因给产品。
- 把页面存在某段文字当成用户已经发现并理解。
- 使用共享登录态，把熟悉后的表现说成首次可用。
- 把自然任务改写成测试 checklist，让人物主动找预期缺陷。
